# v2.0.0

v1.0.0 からの変更。一次ドキュメントと実装の乖離を防ぐ仕組み（ID、横断照合、変更フロー）と、UI・文章・用語の品質を保つ仕組みを追加した。

ドキュメントの配置が変わるため、v1.0.0 で作ったプロジェクトは「移行手順」に従って移行する。

## 破壊的変更

| 対象 | v1.0.0 | v2.0.0 |
|---|---|---|
| Overview | `docs/PROJECT_OVERVIEW.md` | `docs/D1/PROJECT_OVERVIEW.md` |
| 設計文書と計画 | `docs/*.md` | `docs/D2/*.md` |
| 作業中の記録 | 決まりなし（`planining/`、`docs/reports/` など） | `docs/work/` の決められたサブディレクトリ |
| grill-me-with-goal の作業状態 | `./planining/{プラン名}/` | `./docs/work/planning/{プラン名}/` |
| Issue のフロントマター | `created_at`、`status` | `type`、`plan`、`requirements`、`ui`、`requires` を追加 |
| Issue の実装 | create-local-issue / issue-planning の注記 | implement-issue スキル |

## 追加

### トレーサビリティ

- **ID の規則**（`document-interview/references/ID-Rules.md`）：一次ドキュメント（C）→ Overview（OV）→ 要件（FR / NFR / AC）→ UI の規則（UI）・設計判断（ADR）→ 実装作業（W）→ Issue → テストを ID でつなぐ。各スキルが ID を定義・参照する。
- **spec-analyze**：一次ドキュメントを基準に、文書・計画・Issue・テスト・コードを横断して照合する読み取り専用のスキル（GitHub Spec Kit の analyze に相当）。新しい文脈のサブエージェントで動く。
- **trace_check.py**：未定義の ID、重複定義、下流で参照されていない ID、由来のない定義を機械的に検査する。

### 変更フローと Issue

- **変更 Issue**（`create-local-issue/references/issue-template.md`）：差分（ADDED / MODIFIED / REMOVED）、検索で洗い出す影響範囲、上流への反映を書く。上流への反映が終わるまで完了にしない（OpenSpec の archive に相当）。
- **implement-issue**：Issue 1件を、着手、TDD、検証、新しい文脈でのレビュー、完了まで進める。
- **requires: human**：人の作業を含む Issue を区別する。

### UI

- **UI ガイドライン**（`document-interview/references/UI-Guidelines.md`）：品質方針（Awwwards、Webby Awards、The FWA で受賞できる水準）、操作シナリオと画面遷移の人による確認、セルフチェックの要件（採点基準、比較対象、毎ラウンドの独立採点、上限）。
- documentation-planning は、画面を持つアプリで UI ガイドラインを必ず作成対象にする。implementation-planning は、画面の作業より前に UI 基盤の作業を置く。

### 文章と用語

- **書き方の規則**（`document-interview/references/Writing-Rules.md`）：1要件1文、1文80字以内、表と箇条書きを基本にする。
- **用語集**（`document-interview/references/Glossary.md`）：`docs/D2/GLOSSARY.md` に用語、定義、コード上の名前、使わない言い換えを書く。常に作成する。
- **doc_check.py**：用語集から textlint-rule-prh の辞書を生成する（`glossary-to-prh`）。表のセルの文の長さを検査する（`table-length`）。
- **templates/.textlintrc.json、.textlintignore**：textlint-rule-preset-ja-technical-writing と prh の設定。

### テンプレート

- **templates/AGENTS.md、templates/CLAUDE.md**：ディレクトリ構成と規則をエージェントに伝える。CLAUDE.md は `@AGENTS.md` で取り込む。

## 変更

- create-local-issue と issue-planning の「実装を進める／進めない」の矛盾を解消した。どちらも Issue の作成だけを行う。
- 「Codex」の表記を「エージェント」に変更した。
- discovery-interview の frontmatter の誤り（`discription`）を修正した。

## 削除

- `skills-lock.json` を削除した。
- `memo.md` を Git の管理から外した。

## 移行手順（v1.0.0 で作ったプロジェクト）

1. スキルを v2.0.0 で入れ直す。
2. 文書を移す。
   - `docs/PROJECT_OVERVIEW.md` → `docs/D1/`
   - `docs/` 直下の設計文書と計画 → `docs/D2/`
   - レポート、メモ、チェックリスト → `docs/work/` のサブディレクトリ
3. `templates/AGENTS.md` と `templates/CLAUDE.md` をコピーし、コマンド欄を埋める。
4. 一次ドキュメント（`spec/`）に `C-NN` を振る。要件の行に由来の ID を、テスト名に要件 ID を追記する。計画の範囲表記（`FR-1〜4`）は列挙に直す。
5. Requirements の用語の節を `docs/D2/GLOSSARY.md` に移す。
6. textlint を導入する（README の「文章と用語の検査」）。
7. `spec-analyze all` を実行し、指摘を create-local-issue で Issue にする。

`trace_check.py` は、移行前の配置（`docs/` 直下）も検査できる。
